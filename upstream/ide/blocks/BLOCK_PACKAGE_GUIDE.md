# Creating New CodyNick Blockly Block Packages

The IDE loads block packages automatically from the `blocks/` folder.

Each package is a `.json` file. To add new functionality, create a new file such as:

```text
blocks/my_custom_blocks.json
```

Then refresh the IDE page.

---

## 1. Basic package structure

```json
{
  "id": "my_custom_blocks",
  "name": "My Custom Blocks",
  "version": "1.0.0",
  "categories": [
    {
      "name": "My Device",
      "colour": "#2563eb"
    }
  ],
  "blocks": [
    {
      "type": "my_device_turn_on",
      "label": "turn my device on",
      "category": "My Device",
      "python": "MyDevice.turn_on(cody)",
      "args": [],
      "output": null,
      "colour": "#2563eb",
      "tooltip": "Turns the device on."
    }
  ]
}
```

The IDE reads all `.json` files in `blocks/`.

---

## 2. Important fields

| Field | Required | Meaning |
|---|---:|---|
| `id` | Yes | Unique package ID. |
| `name` | Yes | Human-readable package name. |
| `version` | Recommended | Package version. |
| `categories` | Recommended | Toolbox categories to create. |
| `blocks` | Yes | List of blocks in this package. |

---

## 3. Block fields

Each block object can contain:

| Field | Required | Meaning |
|---|---:|---|
| `type` | Yes | Unique Blockly block type. Use lowercase letters, numbers, and underscores. |
| `label` | Yes | Blockly message text. Use `%1`, `%2`, etc. where fields should appear. |
| `category` | Yes | Toolbox category name. |
| `python` | Yes | Python code template generated by the block. |
| `args` | Yes | List of input fields used by the block. Use `[]` for no fields. |
| `output` | No | Set to `"Number"`, `"String"`, `"Boolean"`, or `"Array"` for value blocks. Use `null` for statement blocks. |
| `colour` | No | Block colour. |
| `tooltip` | No | Help text shown on hover. |

---

## 4. Argument types

The IDE currently supports these argument kinds:

### Text input

```json
{
  "name": "message",
  "label": "message",
  "kind": "text",
  "default": "Hello"
}
```

Python template example:

```json
"python": "log({message})"
```

Generated Python example:

```python
log("Hello")
```

---

### Number input

```json
{
  "name": "seconds",
  "label": "seconds",
  "kind": "number",
  "default": 1
}
```

Python template example:

```json
"python": "time.sleep({seconds})"
```

Generated Python example:

```python
time.sleep(1)
```

---

### Dropdown input

```json
{
  "name": "state",
  "label": "state",
  "kind": "dropdown",
  "default": "True",
  "options": [
    ["on", "True"],
    ["off", "False"]
  ]
}
```

The first value is the label shown to the user.  
The second value is inserted into the generated Python.

Python template example:

```json
"python": "LED_Matrix.set_pixel(cody, 0, 0, {state})"
```

Generated Python example:

```python
LED_Matrix.set_pixel(cody, 0, 0, True)
```

---

### Colour input

```json
{
  "name": "color",
  "label": "color",
  "kind": "colour",
  "default": "#FF0000"
}
```

Python template example:

```json
"python": "RGB_Matrix.set(cody, 0, {color})"
```

Generated Python example:

```python
RGB_Matrix.set(cody, 0, "#FF0000")
```

The IDE uses Blockly's colour picker when available. If the loaded Blockly build does not include it, the IDE falls back to a colour dropdown.

---

## 5. Statement blocks vs value blocks

### Statement block

Use:

```json
"output": null
```

Example:

```json
{
  "type": "matrix_clear",
  "label": "clear LED matrix",
  "category": "My Device",
  "python": "LED_Matrix.clear(cody)",
  "args": [],
  "output": null,
  "colour": "#7c3aed"
}
```

This block can be placed inside `When CodyNick starts`, `Main Loop`, or other statement areas.

---

### Value block

Use an output type:

```json
"output": "Number"
```

Example:

```json
{
  "type": "read_temperature_custom",
  "label": "custom temperature",
  "category": "My Device",
  "python": "Temperature_Sensor.read(cody)",
  "args": [],
  "output": "Number",
  "colour": "#22c55e"
}
```

This block produces a value and can be used inside conditions, math blocks, variables, etc.

---

## 6. Template placeholders

Placeholders use the argument name in braces:

```json
"python": "Seven_Segment.display(cody, {device}, {value})"
```

With arguments:

```json
[
  {
    "name": "device",
    "kind": "dropdown",
    "default": "'STANDALONE'",
    "options": [
      ["Standalone", "'STANDALONE'"],
      ["UltraSeg", "'ULTRASEG'"]
    ]
  },
  {
    "name": "value",
    "kind": "number",
    "default": 123
  }
]
```

Generated Python:

```python
Seven_Segment.display(cody, 'STANDALONE', 123)
```

## 7. Complete example

```json
{
  "id": "example_extra_blocks",
  "name": "Example Extra Blocks",
  "version": "1.0.0",
  "categories": [
    {
      "name": "Examples",
      "colour": "#db2777"
    }
  ],
  "blocks": [
    {
      "type": "example_display_warning",
      "label": "display warning %1",
      "category": "Examples",
      "python": "LED_Matrix.display_text(cody, {text}, 'fast')",
      "args": [
        {
          "name": "text",
          "label": "text",
          "kind": "text",
          "default": "WARNING"
        }
      ],
      "output": null,
      "colour": "#db2777",
      "tooltip": "Displays a fast warning message."
    },
    {
      "type": "example_temperature_above",
      "label": "temperature above %1",
      "category": "Examples",
      "python": "(Temperature_Sensor.read(cody) or 0) > {limit}",
      "args": [
        {
          "name": "limit",
          "label": "limit",
          "kind": "number",
          "default": 30
        }
      ],
      "output": "Boolean",
      "colour": "#22c55e",
      "tooltip": "Returns true if temperature is above the selected limit."
    }
  ]
}
```

---

## 8. Notes and limitations

1. Block package files must be valid JSON.
2. Every block `type` must be unique across all packages.
3. The generated Python assumes `from CodyNick import *` and `cody = CN()` are already added by the IDE.
4. The block package only describes the Blockly block and generated Python. The actual Python classes/functions must exist in the runtime environment.
5. For dropdowns, include quotes in the inserted value when the Python value should be a string.

Correct string value:

```json
["CodyJoy Pro", "'CJP'"]
```

Incorrect string value:

```json
["CodyJoy Pro", "CJP"]
```

The incorrect version would generate invalid Python unless `CJP` is a defined variable.
